## 1. 한 줄 정의

**국토교통부 실거래가 데이터로 "진짜 싼 급매"인지 검증해, 아파트 매수자의 가격 판단을 돕는 플랫폼.**

호가가 아니라 *실거래가* 기준으로, 같은 단지·같은 전용면적의 실제 거래 중앙값보다 5% 이상 싼 매물만 "검증된 급매"로 보여주고, 산출 근거(비교에 쓴 거래의 계약일·층·가격·표본 수·기간)를 그대로 공개한다.

## 2. 왜 만드는가

- 부동산 앱과 중개사무소의 "급매"는 누구나 붙일 수 있는 홍보 문구다. 무엇과 비교해 얼마나 싼지 근거를 보여주는 곳이 없다.
- 매수자는 인생 최대 금액을 쓰면서 판단 기준 없이 판매자·중개사 정보에 의존한다. 국토부 실거래가는 공개돼 있지만 단지·면적·시점을 맞춰 수작업으로 대조해야 한다.
- 기존 서비스의 한계: 매물 플랫폼(네이버부동산·직방)은 호가 나열, 시세 서비스(호갱노노·아실)는 단지 시세까지만. "지금 올라온 이 매물이 실거래 대비 얼마나 싼가"를 판정하는 곳은 없다.
- 중개사 인터뷰에서 확인한 이중 비대칭: 공개된 급매는 믿기 어렵고, 믿을 만한 'A급' 급매는 공동중개 인맥 안에서 먼저 소화돼 일반 매수자 눈에 안 보인다.

**만들고 싶은 변화:** '급매'가 마케팅 문구가 아니라 데이터로 검증된 정보가 되는 것.

## 4. 급매 판정 방식 (핵심 로직)

| 항목 | 현재 구현 | 비고 |
|---|---|---|
| 기준 실거래가 | 동일 단지 + 동일 전용면적(㎡ 정수)의 최근 36개월 실거래 **중앙값** | 1순위. 없으면 ±2㎡ 근접 면적 → 지역(구+평형대) 시세 → 얇은 단지값(신뢰도 low) 순 |
| 최소 표본 | 3건 미만이면 단지 기준가로 신뢰하지 않음 | 등록 흐름 기준. 수집 매물 파이프라인도 동일 |
| 급매 기준 | 할인율 = (기준가 − 매도가) / 기준가 ≥ **5%** | 수집 매물은 40% 초과를 이상치로 제외 |
| 근거 공개 | 산출 방식 문구("동일 단지 59㎡ · 2023-07~2026-07 189건 중앙값"), 평형별 요약표, 최근 실거래 내역(계약일·층·가격) | `price_basis` 스냅샷으로 매물에 저장 |
| 제외 거래 | 해제(취소) 거래 제외 · 직거래 제외 | 수집 단계 필터 + 판정 함수. 직거래는 수집기에 거래유형 열이 추가된 뒤(재수집 필요) 실제로 걸러진다 |
| 거래 시점 | 최근 12개월 표본 ≥3 이면 12 → 아니면 24 → 36개월 | 지수 조정 없이 "비교 대상 거래를 고르는 규칙"으로 구현 (추정 금지 원칙) |
| 층 구간 | 저층(1~3) · 중층 · 고층(최고층 ≥10 일 때 상위 3개 층) — 같은 구간 거래 ≥3 이면 그 거래만 | 매물 층 텍스트("저층/중층/고층")도 인식 |
| 판정 보류 | 36개월 표본 3건 미만 또는 단지 데이터 없음 → 기준가·할인율 null, "판정 보류" 배지, 급매 목록·지도·홈 제외 | 화면·등록 미리보기에 사유 표시 |
| 신뢰도 등급 | high(≥5건) · medium(3~4건) | medium 은 "(표본 적음)" 표기 |
| 공통 판정 함수 | `src/utils/priceBasis.js` — 앱(등록·미리보기)과 파이프라인(재계산)이 동일 코드 | 설계: `docs/superpowers/specs/2026-09-29-price-basis-judgment-design.md` |
| 백테스트 | 과거 실거래 한 건을 "그 달의 매물"로 보고, 그 달보다 앞선 거래만으로 구한 기준가와 비교 · 급매 판정은 이후 6개월 시세로 채점 | **코드 완료 (2026-09-29), 실데이터 실행 전.** 운영 판정 함수를 그대로 호출. 산출: 기준가 오차·정밀도·재현율·규칙 요소별 효과. 설계: `docs/superpowers/specs/2026-09-29-backtest-design.md` |

원칙: **실거래가와 호가를 절대 혼용하지 않는다.** 모든 분석은 과거 데이터의 패턴 설명이며 투자 권유·미래 예측이 아니다(법적 고지 유지).

```
국토교통부 실거래가 OpenAPI  (254 시군구 × 최근 36개월)
   │  fetch-trades.py  (해제 거래 제외, 증분 --since 병합)
   ▼
scripts/data/*.csv  ──► build-complex-prices / build-price-trends / build-complex-trades
   │                     (단지×면적 중앙값 · 평형대 월별 추이 · 단지별 개별 거래)
   ▼
public/data/*.json  ◄── import-listings.py (매물 엑셀 → 단지 매칭 → 급매 선별 → 지오코딩 → 근거 베이크)
   │  properties(387) · complex_prices(4,000) · market_snapshots · property_reports(15) · ai_market_reports
   │  ◄── generate-reports.mjs / generate-market-report.mjs (Gemini, 실데이터 그라운딩)
   ▼
React SPA (Vite)  ── src/lib/dataClient.js 가 모드를 결정, 서비스 코드는 모드를 모른다
   ├─ 읽기(매물·시세·리포트): 번들 JSON  (+ 하이브리드: Supabase 매물 오버레이, 2.5초 타임아웃)
   ├─ 인증·쓰기(가입·등록·신청·승인): 로컬 = localStorage  /  하이브리드 = Supabase
   ├─ Storage: 신청 서류 · 3D 모델 · (예정) 360 파노라마
   └─ Edge Function: inspection-report (사진 → Gemini → property_inspections)
   ▼
Vercel  ── dist/ + properties/<id>/index.html × 387 + sitemap.xml + robots.txt
```

**두 가지 실행 모드** (`.env.local`의 Supabase 키 유무로 자동 결정):

| | 로컬 데모 모드 | 하이브리드 모드 (라이브) |
|---|---|---|
| 목적 | 클론 → `npm install` → `npm run dev`만으로 전 기능 시연 | 실제 회원·중개사·매물 등록 |
| 읽기 | 번들 JSON | 번들 JSON + Supabase 신규·수정분 병합 |
| 인증·쓰기 | 브라우저 localStorage(mock 계정 시드) | Supabase Auth + Postgres(RLS) |
| 백엔드가 잠들면 | 영향 없음 | 읽기 정상, 쓰기만 오류 안내 |
| 라이브 전용 기능 | 3D 업로드·AI 점검 생성 비활성 | 활성 |

설계 원칙: **백엔드가 잠들어도 사이트는 살아 있다.** 무료 티어는 7일 무활동 시 일시정지되므로 읽기는 번들이 우선이다.

| 실거래 원본 | 1,537,230행 (전국 254 시군구 × 36개월) | 2026-07까지 (광주·전남은 API 장애로 2026-06까지) |
| 단지×면적 중앙값 | CSV 83,103행 → 번들은 표본 상위 **4,000행** | 2026-07 |
| 매물 | 387건 — 인천 209 · 강원 139 · 서울 39 | 기준가 2026-08-27 재계산 |

매물 387건은 더미가 아니라 매물 엑셀 20,997행에서 할인율 5~40% 필터를 통과한 실데이터다. 다만 원본 엑셀에 중개사 정보가 없어 전부 "급매 운영팀", 연락처 공란이다. 매물 이미지 372건은 외부(호갱노노) 핫링크다.

**알려진 데이터 한계:** 앱이 읽는 단지 시세 번들이 4,000행뿐이라 자기 매물 387건 중 80건만 매칭된다. 해소 경로는 마련됨 — 단지×면적 개별 실거래 테이블(`complex_trades`, 하이브리드는 Supabase 전체 83k행, 로컬은 상위 4,000행 번들)을 데스크톱 파이프라인이 생성·적재하면 등록 시 어느 단지든 판정된다. 그 전까지 번들 밖 단지는 "판정 보류"로 정직하게 등록된다(0% 할인율 아님).

## 11. 수익 모델 (사업계획서 요약)

- **1차 고객 = 공인중개사.** 이미 네이버부동산·직방에 월 광고비를 내는, 지불 의사가 검증된 고객군.
- **팔지 않는 것:** 노출 순위. 광고비 낸 매물이 잘 보이는 구조가 근거 없는 '급매' 홍보의 원인이므로, 노출은 검증된 할인율과 정보 충실도로만 결정한다.
- **파는 것:** 중개사 멤버십(등록 매물 수 구간제 월 정액) — ▲등록·검증·관리 도구 ▲"검증된 급매" 배지 ▲근거를 본 구매 의향 높은 고객 연결. 가격은 파일럿 중개사와 시장검증으로 확정.
- 매수자는 핵심 기능 무료. 프리미엄(실시간 알림·단지 심층 리포트)은 이후.
- 장기: 주택담보대출 비교·이사·인테리어 제휴 수수료(노출과 무관), 검증 데이터 B2B 라이선스.
- 초기 확보 순서: 공급(중개사) 먼저 — 한 지역, 5곳 내외 파트너 중개사무소 무료 온보딩 → 매수자는 단지 페이지 검색 유입 + 관심 단지 알림.

## 14. 원칙과 정책

- 모든 가격 주장은 실거래 데이터로 증명하고 산출 근거를 붙인다. 추정·과장·날조하지 않는다(없는 지표·후기·실적을 만들지 않는다).
- 백엔드가 잠들어도 사이트는 살아 있다. 클론 후 `npm install` 한 번으로 전 기능이 동작한다.
- 용어: "급매"(중앙값 대비 5%+), "초급매"(더 깊은 할인). 실거래가와 호가 혼용 금지.
- 개인정보: 매물 수집 시 중개사무소명·전화·등록번호를 수집하지 않는다(스키마에서 배제). 중개사 연락처는 본인이 포털에서 입력한 것만.
- 법적 리스크(기록): 외부 사이트 매물 크롤링은 이용약관·DB권 침해 소지가 있어 산출물을 git·배포에서 격리하고 봇 차단 시 우회하지 않는다(2026-08-27 사용자 결정). 이미지 핫링크 372건은 자체 이미지 확보 전까지 유지.
- 공인중개사법상 매물 표시·광고 의무사항을 등록 단계에서 검증하도록 설계.
- 브랜드: 이름 "급매 (Geupmae)". 비주얼은 확정 아님 — 구속력 있는 것은 "실거래 데이터로 증명하는 검증된 급매"라는 컨셉.
