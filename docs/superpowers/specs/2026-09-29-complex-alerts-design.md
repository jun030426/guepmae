# 관심 단지 급매 알림 — 구독 저장 (발송 전 단계)

작성일: 2026-09-29
상태: 구독 저장·관리·지표까지 구현. 발송은 메일 서비스 키가 필요해 데스크톱 작업으로 분리 (`docs/DESKTOP_TODO.md` F)

## 1. 배경

사업계획서는 관심 단지 급매 알림을 재방문의 "핵심 장치"이자 파일럿 지표("알림 신청 수")로 꼽는다.
급매는 속도가 생명이라, 매수자가 매일 들어와 확인하는 대신 조건에 맞는 매물이 검증되는 순간 알려주는 것이 서비스의 약속이다.

발송에는 메일 서비스 API 키와 도메인 인증이 필요하다. 이 노트북 세션에서는 키 없이 검증 가능한 범위 —
**신청을 받고, 저장하고, 본인이 관리·해지하고, 운영이 수요를 집계하는 것** — 까지 만든다.

## 2. 범위

| 포함 | 제외 (다음 단계) |
|---|---|
| 매물 상세의 "이 단지 급매 알림" 신청 카드 | 메일 발송 (edge function + 메일 서비스) |
| 구독 저장 (하이브리드 Supabase / 로컬 localStorage) | 이중 확인(double opt-in) 메일 |
| 내 알림 페이지 `/alerts` — 목록·해지·해지 링크(`?token=`) 처리 | 카카오 알림톡·푸시 |
| 관리자 통계 — 활성 신청 수·상위 단지 | 지역·가격대 단위 알림 |
| 발송 대상 선정 규칙 `matchAlerts` (순수 함수, 테스트) | |

## 3. 구독 모델

```jsonc
// complex_alerts
{
  "email": "buyer@example.com",
  "complex": "두산위브",                 // 국토부 기준 단지 정식명
  "gu": "인천광역시 부평구",
  "area_m2": 59,                        // null = 단지 전체 평형
  "min_discount": 5,                    // 5~40
  "source_property_id": "gm-1b04c45e43",
  "status": "active",                   // 'active' | 'unsubscribed'
  "unsubscribe_token": "uuid",          // 클라이언트가 생성 — 비로그인 해지용
  "confirmed_at": null                  // 발송 시작 시 이중 확인에 사용
}
```

- 단지 식별: 수집·재계산 매물은 `price_table.complexName` + `region`, 중개사 등록 매물은 등록 시 `price_basis.complexName`·`gu` 로 저장한다(`complexOf`). 단지를 알 수 없는 매물에는 카드를 띄우지 않는다.
- 중복: 같은 이메일·단지·구·평형의 활성 구독은 하나 (부분 유니크 인덱스). 중복 신청은 오류가 아니라 "이미 신청됨"으로 안내한다.

## 4. 권한 (RLS)

| 동작 | 누구 | 방법 |
|---|---|---|
| 신청(insert) | 누구나 (비로그인 포함) | 활성 상태로만, `confirmed_at`·`unsubscribed_at` 은 비워야 함 |
| 조회(select) | 본인 이메일로 로그인한 사용자 / 운영진(admin·owner) | 비로그인은 읽지 못한다 |
| 해지 | 토큰을 아는 사람 | `unsubscribe_alert(token)` security definer 함수 |

비로그인 사용자는 자기 행을 다시 읽을 수 없으므로, 신청 시 만든 토큰을 이 기기(localStorage `geupmae:my-alerts`)에 남겨 `/alerts` 에서 해지할 수 있게 한다.

**알려진 한계 — 타인 이메일 도용 신청.** 비로그인 insert 를 열어 두면 남의 이메일로 신청할 수 있다. 지금은 발송이 없어 피해가 없고, 발송을 시작할 때 이중 확인(확인 메일의 링크를 눌러야 `confirmed_at` 기록 → 그 구독만 발송)으로 막는다.

## 5. 발송 대상 규칙 (`matchAlerts`)

매물이 운영 검증 완료되고, 판정 보류가 아니며, 할인율이 구독의 최소 할인율 이상일 때 —
같은 단지·구의 활성 구독 중 평형 조건이 맞는 것(전체 평형 구독 포함). 미검증·보류 매물은 알리지 않는다.

## 6. 개인정보

- 수집 항목: 이메일 하나. 목적: 관심 단지 급매 알림. 보유: 해지 시까지.
- 신청 폼에 항목·목적·보유기간을 표시하고 동의 체크를 받는다. 동의하지 않아도 매물 열람에는 제한이 없다.
- 해지는 언제든 `/alerts` 또는 메일의 해지 링크에서 한 번에.

## 7. 화면 문구 원칙

발송이 아직 없으므로 "알림을 보내드립니다"라고 단정하지 않는다.
신청 완료 화면: "알림 신청이 저장되었습니다 … 알림 발송은 시범 운영 준비 중이며, 시작되면 이 주소로 안내드립니다."

## 8. 검증 기준

1. 로컬: 상세에서 신청 → 완료 문구 → `/alerts` 에 표시 → 해지 → 목록에서 사라짐. 같은 조건 재신청은 "이미 신청됨".
2. 이메일 형식 오류·동의 미체크는 저장되지 않는다.
3. 관리자 화면에 활성 신청 수와 상위 단지가 보인다.
4. 단지를 알 수 없는 매물(보류 등록)에는 카드가 보이지 않는다.
5. `/alerts?token=…` 진입 시 확인 후 해지.
6. 하이브리드: 마이그레이션 적용 후 비로그인 신청이 저장되고, 비로그인 조회는 거부된다(RLS).

## 9. 발송 단계 (데스크톱) 개요

1. 메일 서비스(Resend 등) 키·발신 도메인 인증
2. Edge Function `send-complex-alerts`: 매물 검증 시(또는 하루 1회) `matchAlerts` 규칙으로 대상 선정 → 메일 발송 → 발송 로그 테이블
3. 이중 확인 메일 + `confirmed_at`
4. 메일 하단 해지 링크 `https://guepmae.vercel.app/alerts?token=<unsubscribe_token>`
