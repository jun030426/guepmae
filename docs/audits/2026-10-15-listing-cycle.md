# 매물 등록·승인·공개·수정·문의 전체 흐름 검증

대상: `jun030426/guepmae`, 운영 `https://guepmae.vercel.app`, Supabase `oormfipegcfbhvctikfl`.

## 수정한 문제

- 관리자 검증 취소가 매물 객체 대신 ID 문자열을 넘겨 실패하던 호출을 수정했다. ID와 revision을 함께 전달하며 오래된 승인·취소 요청은 거절한다.
- 중개사 수정 화면에 문의 전화번호를 추가했다. 서버에서 번호 형식을 검증하고 전화번호만 변경하며 중개사 이름·이메일·인증 상태·소유자는 입력으로 변경할 수 없다. 번호 변경도 승인 대기로 돌아간다.
- 등록 시 짧거나 잘못된 번호를 입력하면 사진 업로드 전에 안내한다. 서버 검증도 적용했다. 이는 번호 형식 검증이며 실제 번호 소유·연결 여부를 인증하는 기능은 아니다.
- 조회·문의 집계 함수가 비공개 매물을 받던 문제를 수정했다. 승인된 매물만 집계하고 담당자 UID·관리자·정지 계정의 조회를 제외한다. 클라이언트는 서버가 거절한 집계를 완료로 기록하지 않는다.
- 지역 필터에서 제외돼 있던 강원·세종·울산·제주를 추가했다. 신규 등록 매물도 전국 시도에서 검색할 수 있다.
- 내 매물 빈 화면의 자동 AI 리포트 생성 문구를 실제 기능에 맞췄다. 목록에 최근 실거래일 스냅샷이 없으면 빈칸 대신 상세 리포트 확인 안내를 표시한다.

## 실제 검증

실존 가입자를 변경하지 않고 확정 이메일의 테스트 중개사 2명과 관리자 1명을 준비했다. 매물은 제목·설명에 기능 검증용·거래 불가를 표시했다. 가입 및 OTP 배송 검증은 이번 범위가 아니며 이전 가입 점검 기록을 참조한다.

| 단계 | 결과 |
| --- | --- |
| 등록 | 브라우저에서 세경3차아파트·49㎡·3층을 선택, 8,000만 원으로 제출. 기준가 8,600만 원·할인율 7%, revision 1, 승인 대기 저장 |
| 승인 전 접근 | 작성자 미리보기 가능. 비로그인 상세는 찾을 수 없음, Data API와 다른 중개사 조회도 제외 |
| 관리자 승인 | 실제 승인 버튼으로 revision 2·공개 상태 전환. 운영 목록·상세·문의 섹션 표시 |
| 수정 | 제목·설명·가격 7,900만 원·전화번호 변경. revision 3·승인 대기, 할인율 8.1% 재계산, 공개 상세 접근 차단 |
| 권한·동시 수정 | 다른 중개사의 수정 요청 거절, 과거 revision 승인 요청 409, 승인 대기 매물 집계 거절 |
| 재승인·취소 | 관리자 UI 재승인 성공. 검증 취소 확인창 처리 후 revision 5·비공개, 다시 승인 후 공개 |
| 지역 검색 | 강원 조건으로 춘천 테스트 매물 표시, URL 필터 상태 유지 |
| 문의 | 새 번호의 tel 링크 및 담당자 mailto 링크 확인. 이메일 링크 키보드 실행 후 DB 문의 수 0→1. 실제 통화·메일 발송은 수행하지 않음 |
| 집계 권한 | 전화·이메일 이벤트 RPC 수용, 담당 중개사 통계 및 내 매물 화면 표시, 다른 중개사에게 해당 통계 미노출, 담당자·관리자 조회 집계 제외 |
| 중복 문의 | 동일 브라우저에서 재실행해 문의 집계가 증가하지 않음. API 검증용으로 별도 추가한 이벤트 2건은 별도로 구분하고 모두 정리 |
| 운영 재검증 | 배포 후 운영 화면에서 연락처를 다시 수정해 revision 7·비공개, 관리자 승인 후 revision 8·공개. 최종 tel 링크에 새 번호 반영 |

현재 문의 기능은 전화·메일 앱 연결과 버튼 사용 집계다. 사이트 내부 메시지함, 예약 확정, 실제 통화 완료·메일 도착 확인 기능은 없다. 일별 브라우저 중복 제거는 익명 사용 통계용이며 서버 단에서 방문자 신원을 판별하는 기능은 아니다.

이번 사이클은 사진 없는 매물로 검증했다. 실제 세경3차 사진·360 파일은 이전 `2026-10-15-photo-tour.md`에서 검증했으며 이번 공개 테스트에 실내 사진을 사용하지 않았다.

## 배포와 검증

- Node 회귀 테스트 244개 통과. 실제 PostgreSQL 호환 PGlite에서 운영 마이그레이션·서버 처리·RLS·revision·문의 권한을 함께 실행했다.
- 프로덕션 빌드 성공. 기존 번들 크기 안내는 남아 있다.
- 마이그레이션 `complete_property_cycle`을 급매 DB에 적용했다. 서비스 전용 저장 RPC의 실행 권한과 기존 소유권·승인 잠금 규칙을 유지했다.
- `property-write` Edge Function version 2 배포, JWT 검증 유지.
- 코드 커밋 `3b5073b` main 푸시 후 Vercel 운영 배포 성공 확인. 운영 수정·재승인·필터·연락처 반영까지 다시 검증했다. 마지막 카드 안내 문구와 이 기록을 후속 커밋에 포함했다.
- 운영 브라우저 콘솔 오류 없음. 브라우저 도구가 한 차례 지연됐으나 재연결 후 동일 흐름을 완료했다.
- 보안 advisor의 기존 경고 종류·건수는 증가하지 않았다. 기존 search_path·pg_trgm 위치·암호 유출 보호 설정 경고는 별도 잔여 항목이다. 의도된 제한 RPC와 직접 접근을 막은 통계 테이블 알림도 유지된다. [공식 DB 함수 보안 설명](https://supabase.com/docs/guides/database/functions), [advisor 설명](https://supabase.com/docs/guides/database/database-linter).
- 원래 작업 폴더에는 정확한 릴리스 패치의 적용 검사를 거쳐 반영한다. 기존 미커밋 작업과 환경 변수는 보존한다.

## 정리

테스트 매물 1개·그 매물의 통계·임시 중개사 승인 신청·임시 계정 3개를 정확한 ID로 삭제했다. 검증 후 조회 결과 매물 0, 테스트 통계 0, 테스트 계정 0, 테스트 신청 0이며 검증 전 매물 집합과 일치했다. 검증용 인증 정보 파일도 삭제했다. 증빙 이미지는 개인 로컬 백업에만 저장했다.
