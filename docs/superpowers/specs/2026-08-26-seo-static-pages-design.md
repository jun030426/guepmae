# 급매 — 검색 유입 기반 구축 (정적 페이지 생성) 설계

- 작성일: 2026-08-26
- 대상: https://guepmae.vercel.app / `jun030426/guepmae`
- 범위: **B단계(검색 유입) 단독**. A단계(중개사 PRO 유료화)·C단계(대출 비교)는 후속 스펙으로 분리한다.

---

## 1. 배경

창업동아리 지원사업 품목으로서 수익화 가능성이 판단 기준이다. 수익 모델 논의 결과
과금 주체는 **중개사(급매 PRO)**, 보조 수익원은 **광고**로 정했다. 그러나 두 모델 모두
전제 조건이 갖춰지지 않았다.

- 중개사가 돈을 내는 이유는 "여기 올리면 문의가 온다"이다. 문의는 트래픽에서, 트래픽은 검색에서 나온다.
- 광고 단가는 트래픽의 함수다. 현재 트래픽은 사실상 0이다.

따라서 **유입 → 전환 → 과금** 순서로, 유입 기반부터 만든다.

## 2. 해결하려는 문제

배포된 사이트는 순수 SPA다. `dist/`에 HTML이 `index.html` 하나뿐이고,
sitemap·robots.txt·페이지별 메타 태그가 없다.

- 매물 395건이 모두 같은 `<title>`("급매 | 실거래가로 증명된 급매 플랫폼")과 같은 설명을 공유한다.
- 검색엔진 입장에서 이 사이트는 **페이지가 1개**다.
- 부동산은 "○○아파트 84㎡ 급매" 같은 롱테일 검색 유입이 핵심인데, 그 경로가 완전히 막혀 있다.

## 3. 접근 방식 선택

| 안 | 방식 | 판정 |
|---|---|---|
| **B1** | 빌드 후 Node 스크립트가 라우트별 정적 HTML 생성 | **채택** |
| B2 | `vite-react-ssg` 도입 (진짜 React SSG) | 기각 — 라우팅 구조 개편 필요, 리스크 대비 이득 작음 |
| B3 | puppeteer 프리렌더 | 기각 — 빌드 395×약1초, 의존성 무거움 |

**B1 채택 근거**: 데이터가 빌드 시점에 `public/data/*.json`으로 전부 확정돼 있다.
브라우저를 띄우거나 프레임워크를 갈아탈 이유가 없다. 앱 코드를 건드리지 않으므로
기존 동작을 깨뜨릴 위험이 가장 낮다.

## 4. 설계

### 4.1 구조

```
npm run build                          기존 Vite 빌드 (변경 없음)
  └─ node scripts/generate-static-pages.mjs      신규
       ├─ public/data/properties.json 읽기 (395건)
       ├─ dist/properties/<id>/index.html  × 395
       ├─ dist/sitemap.xml
       └─ dist/robots.txt
```

`package.json`의 `build` 스크립트를 `vite build && node scripts/generate-static-pages.mjs`로
변경해 Vercel 빌드에서 자동 실행되게 한다.

### 4.2 생성되는 매물 페이지

`dist/index.html`을 템플릿으로 삼아 매물별로 다음을 치환·주입한다.

- **`<title>`** — `{단지명} {면적} 급매 | 시세 대비 {할인율}% 저렴 - 급매`
- **`<meta name="description">`** — 매물별 요약 (주소·매도가·기준 실거래가·할인율·최근 실거래일)
- **`<link rel="canonical">`** — `https://guepmae.vercel.app/properties/{id}`
- **OG 태그** — `og:title` / `og:description` / `og:url` / `og:type`
- **JSON-LD** — schema.org 구조화 데이터. 검색결과 리치 스니펫에 가격·위치 노출
- **`#root` 내부 초기 HTML** — 매물명·주소·매도가·기준 실거래가·할인율·실거래 내역 요약을
  실제 마크업으로 넣는다. JS를 실행하지 않는 크롤러가 읽을 내용이다.
  `src/main.jsx`가 `ReactDOM.createRoot()`를 쓰므로(`hydrateRoot` 아님)
  React가 이 내용을 그대로 교체한다 — 하이드레이션 불일치가 발생하지 않고
  사용자 화면에도 영향이 없다. **이 스펙은 그 전제 위에 서 있으므로,
  향후 `hydrateRoot`로 바꾸려면 이 설계도 함께 손봐야 한다.**

### 4.3 sitemap.xml

매물 395건 + 주요 페이지(`/`, `/properties`, `/map`, `/report`, `/agent`)를 포함한다.
`lastmod`는 매물의 `last_verified_at`을 사용한다.

### 4.4 robots.txt

전체 크롤 허용 + `Sitemap:` 지시자로 sitemap 위치를 명시한다.
중개사 포털(`/agent/*`)과 관리자(`/admin`)는 `Disallow`로 제외한다.

### 4.5 라우팅 충돌 처리

현재 `vercel.json`은 모든 경로를 `index.html`로 rewrite한다.

```json
{ "rewrites": [{ "source": "/(.*)", "destination": "/index.html" }] }
```

이 설정이 생성된 정적 파일을 덮을 수 있다. **실제 파일이 존재하면 그것을 우선 서빙하고,
없을 때만 `index.html`로 폴백**하도록 조정한다. 같은 이유로 `public/_redirects`도
정적 파일 우선 규칙과 충돌하지 않는지 함께 확인한다.

이 부분은 로컬에서 완전히 재현되지 않으므로 **배포 후 실제 URL로 검증**한다.

## 5. 검증 기준

구현 완료 판정은 다음을 **배포된 URL에서** 모두 만족할 때로 한다.

1. `curl https://guepmae.vercel.app/properties/{id}` 응답 raw HTML에 해당 매물의
   단지명·매도가가 포함된다 (JS 실행 없이).
2. 서로 다른 매물 3건의 `<title>`이 모두 다르다.
3. `https://guepmae.vercel.app/sitemap.xml`이 200으로 응답하고 URL 400개 내외를 포함한다.
4. `https://guepmae.vercel.app/robots.txt`가 200으로 응답한다.
5. Google Rich Results Test에서 JSON-LD가 오류 없이 인식된다.
6. 기존 SPA 동작이 깨지지 않는다 — 홈·매물·지도·상세·리포트 화면과
   클라이언트 라우팅(링크 클릭 이동)이 종전대로 동작하고 콘솔 오류가 없다.

## 6. 리스크와 한계

- **색인은 즉시 되지 않는다.** 검색엔진 반영에 며칠~몇 주가 걸린다.
  유입 성과는 이번 보고 기간(~2026-08-28) 안에 나오지 않는다.
  보고서에는 "검색 유입 기반 구축"으로 쓰고, 성과 수치를 약속하지 않는다.
- **OG 이미지**는 넣지 않는다. 매물 이미지 372건이 `image.hogangnono.com` 핫링크라
  공유 카드에서 깨지거나 저작권 문제가 될 수 있다. 자체 이미지 확보 후 별도로 다룬다.
- **빌드 산출물이 커진다.** 395개 디렉터리가 추가되나, 각 파일이 작아 배포에 문제되는 규모는 아니다.
- 매물 데이터가 갱신되면 정적 페이지도 함께 재생성돼야 한다. 빌드에 묶여 있으므로
  재배포 시 자동 반영된다.

## 7. 이번 범위에서 제외한 것

- 중개사 PRO 유료화 (A단계) — Supabase 무료 티어 부활, 실인증, 결제 연동. **다음 스펙.**
- 대출 비교 (C단계) — 금감원 금융상품 API를 주택담보대출로 확장. **후속.**
- AI 리포트 확대 — 현재 15/395건. 실시간 생성은 백엔드가 없어 불가하며,
  A단계에서 백엔드가 서면 함께 다룬다.
- 호갱노노 이미지 핫링크 372건 — 당분간 유지하기로 결정.

## 8. 함께 기록해 두는 결정

향후 계획서·보고서에 반영할 확정 사항.

- **지도**: 현재 Google Maps는 정상 동작한다(무료 한도 만료 아님 — 타일 응답·오류 없음 확인).
  다만 부동산 서비스 표준이 카카오맵이므로 **추후 카카오맵으로 전환한다.**
  참고로 `MapView.jsx`에 네이버 지도 구현이 이미 있고 `VITE_NAVER_MAP_CLIENT_ID`만 비어 있다.
- **광고 수익**: 트래픽의 함수이므로 **2단계 수익원**으로 둔다. B단계 완료 후 재검토한다.
  중개사 PRO와 광고가 충돌할 수 있다는 점(유료 중개사 옆 경쟁 광고)을 고려해야 한다.
- **백엔드**: Supabase 무료 티어로 부활시킨다. `geupmae-platform` 프로젝트가 살아 있고
  `subscriptions`·`payments`·`leads`·`partner_applications` 스키마가 이미 설계돼 있다(데이터 0건).
  무료 티어는 7일 미사용 시 일시정지되는 점을 운영에서 감안한다.
